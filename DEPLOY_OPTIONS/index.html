    🎯 Варианты деплоя документации

    Вариант 1: Деплой от имени организации (если репозиторий в организации)

    Если репозиторий принадлежит организации, документация будет доступна по адресу: 

    https://<название-организации>.github.io/<название-репозитория>/

    Настройка: 1. Убедитесь, что репозиторий принадлежит организации 2. Settings → Pages → Source: GitHub Actions 3. Деплой произойдёт автоматически

    Обновите mkdocs.yml: 

    site_url: https://название-организации.github.io/labLexa/
repo_url: https://github.com/название-организации/labLexa
repo_name: labLexa

    Вариант 2: Project Site (рекомендуется)

    Документация будет доступна по адресу репозитория: 

    https://<ваш-username>.github.io/<название-репозитория>/

    Это стандартный вариант - URL не содержит ваш username в начале, только название репозитория.

    Настройка: 1. Settings → Pages → Source: GitHub Actions 2. Деплой автоматический

    Обновите mkdocs.yml: 

    site_url: https://ваш-username.github.io/labLexa/
repo_url: https://github.com/ваш-username/labLexa
repo_name: labLexa

    Вариант 3: Кастомный домен

    Можно использовать свой домен (например, docs.yourdomain.com).

    Настройка:

    1. В GitHub:
    2. Settings → Pages → Custom domain

    3. Введите ваш домен (например, docs.yourdomain.com)

    4. В DNS провайдере:

    5. Создайте CNAME запись: 

      docs.yourdomain.com → ваш-username.github.io

    6. Обновите mkdocs.yml: 

      site_url: https://docs.yourdomain.com/
repo_url: https://github.com/ваш-username/labLexa
repo_name: labLexa

    Вариант 4: Деплой на Netlify/Vercel (без GitHub Pages)

    Netlify

    1. Создайте netlify.toml в корне проекта: 

      [build]
  command = "pip install mkdocs mkdocs-material && mkdocs build"
  publish = "site"

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200

    2. Подключите репозиторий к Netlify:

    3. Зайдите на netlify.com
    4. New site from Git → выберите репозиторий

    5. Netlify автоматически определит настройки из netlify.toml

    6. Результат:

    7. Документация будет на https://random-name.netlify.app
    8. Можно настроить кастомный домен в настройках Netlify

    Vercel

    1. Создайте vercel.json в корне проекта: 

      {
  "buildCommand": "pip install mkdocs mkdocs-material && mkdocs build",
  "outputDirectory": "site",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}

    2. Подключите к Vercel:

    3. Зайдите на vercel.com
    4. Import Project → выберите репозиторий

    5. Vercel автоматически определит настройки

    6. Результат:

    7. Документация будет на https://labLexa.vercel.app
    8. Можно настроить кастомный домен

    Вариант 5: GitHub Pages для репозитория (без username в URL)

    Если репозиторий называется labLexa, документация будет на: 

    https://ваш-username.github.io/labLexa/

    Это стандартное поведение GitHub Pages - URL формируется как username.github.io/repo-name/, а не username.github.io/.

    Какой вариант выбрать?

    Вариант URL Сложность Рекомендация
    GitHub Pages (Project Site) username.github.io/repo-name/ ⭐ Легко ✅ Рекомендуется
    Организация org-name.github.io/repo-name/ ⭐ Легко ✅ Если есть организация
    Netlify random-name.netlify.app ⭐⭐ Средне ✅ Если нужен кастомный домен
    Vercel repo-name.vercel.app ⭐⭐ Средне ✅ Если нужен кастомный домен
    Кастомный домен docs.yourdomain.com ⭐⭐⭐ Сложно ✅ Если есть свой домен

    Текущая настройка

    Проверьте текущий URL в mkdocs.yml: 

    site_url: https://your-username.github.io/labLexa/
repo_url: https://github.com/your-username/labLexa

    Замените your-username на: - Ваш реальный GitHub username (для Project Site) - Название организации (если репозиторий в организации) - Кастомный домен (если используете свой домен)

    Быстрая проверка

    После деплоя проверьте: 1. Actions → должен быть успешный деплой ✅ 2. Откройте URL документации в браузере 3. Если не открывается - подождите 1-2 минуты (GitHub обновляется с задержкой)
