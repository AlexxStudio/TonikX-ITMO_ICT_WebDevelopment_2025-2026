    📦 Клонирование и деплой документации

    Что происходит при клонировании?

    Просто клонирование репозитория НЕ запускает деплой автоматически.

    Но если в репозитории уже есть: - ✅ Файл .github/workflows/docs.yml (уже есть) - ✅ Файлы документации в docs/ (уже есть) - ✅ Файл mkdocs.yml (уже есть)

    То после настройки GitHub Pages деплой будет работать автоматически.

    Пошаговая инструкция

    Шаг 1: Клонирование репозитория

    git clone https://github.com/username/labLexa.git
cd labLexa

    Шаг 2: Настройка GitHub Pages (делается ОДИН РАЗ)

    Это нужно сделать в настройках репозитория на GitHub:

    1. Откройте репозиторий на GitHub
    2. Перейдите в Settings → Pages
    3. В разделе Source выберите "GitHub Actions"
    4. Сохраните

    ⚠️ Важно: Это нужно сделать в веб-интерфейсе GitHub, не через git!

    Шаг 3: Обновите URL в mkdocs.yml (опционально)

    Откройте mkdocs.yml и замените плейсхолдеры на реальные значения:

    site_url: https://ваш-username.github.io/labLexa/
repo_url: https://github.com/ваш-username/labLexa
repo_name: labLexa

    Шаг 4: Запушьте изменения

    git add .
git commit -m "Configure documentation deployment"
git push origin main

    Шаг 5: Деплой запустится автоматически

    После push: 1. Перейдите в Actions на GitHub 2. Найдите workflow "Deploy Documentation" 3. Дождитесь завершения (зелёная галочка ✅) 4. Документация будет доступна по адресу: 

    https://ваш-username.github.io/labLexa/

    Что уже готово в репозитории?

    ✅ Workflow файл: .github/workflows/docs.yml - уже настроен
    ✅ Документация: все файлы в docs/ - уже есть
    ✅ Конфигурация: mkdocs.yml - уже настроен

    Осталось только: 1. Настроить GitHub Pages в Settings → Pages (один раз) 2. Запушить изменения

    Проверка после деплоя

    После успешного деплоя:

    1. В Actions:
    2. Должна быть зелёная галочка ✅

    3. В логах должно быть "Deploy to GitHub Pages" успешно

    4. В Settings → Pages:

    5. Должно быть написано "Your site is live at..."

    6. Будет показан URL документации

    7. Откройте URL в браузере:

    8. Должна открыться главная страница документации
    9. Все разделы должны быть доступны

    Если деплой не работает

    Проблема: "No workflow file found"

    Решение: Убедитесь, что файл .github/workflows/docs.yml закоммичен и запушен

    Проблема: "Pages build failed"

    Решение: - Проверьте синтаксис mkdocs.yml - Проверьте, что все файлы в nav: существуют в docs/

    Проблема: "Workflow не запускается"

    Решение: - Проверьте, что в Settings → Pages выбран "GitHub Actions" - Убедитесь, что вы пушите в ветку main - Проверьте, что изменены файлы в docs/ или mkdocs.yml

    Проблема: "Нет прав на деплой"

    Решение: - Владелец репозитория должен дать вам права Write или Admin - Или настройте GitHub Pages в Settings → Pages

    Краткая версия

    # 1. Клонируйте репозиторий
git clone https://github.com/username/labLexa.git
cd labLexa

# 2. Настройте GitHub Pages (в веб-интерфейсе GitHub)
# Settings → Pages → Source: GitHub Actions

# 3. Обновите mkdocs.yml (замените your-username на реальный)

# 4. Запушьте изменения
git add .
git commit -m "Deploy docs"
git push origin main

# 5. Деплой произойдёт автоматически через 1-2 минуты
# Проверьте в Actions → Deploy Documentation

    Важно помнить

    • ⚠️ Клонирование само по себе не деплоит - нужен push
    • ⚠️ GitHub Pages нужно настроить один раз в веб-интерфейсе
    • ✅ После настройки деплой автоматический при каждом push в main
    • ✅ Workflow уже настроен - ничего дополнительно делать не нужно
