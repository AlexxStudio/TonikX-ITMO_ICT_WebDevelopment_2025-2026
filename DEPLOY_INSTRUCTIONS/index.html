    📚 Инструкция по деплою документации

    Быстрый старт (для деплоя)

    Шаг 1: Настройка GitHub Pages (делается один раз владельцем репозитория)

    1. Откройте репозиторий на GitHub
    2. Перейдите в Settings (настройки репозитория)
    3. В левом меню найдите раздел Pages
    4. В разделе Source выберите "GitHub Actions" (не "Deploy from a branch")
    5. Сохраните изменения

    Шаг 2: Деплой (автоматический)

    После настройки GitHub Pages:

    1. Закоммитьте и запушьте изменения: 

      git add .
git commit -m "Add documentation"
git push origin main

    2. Проверьте деплой:

    3. Перейдите на вкладку Actions в репозитории
    4. Найдите workflow "Deploy Documentation"
    5. Дождитесь завершения (зелёная галочка)

    6. Обычно занимает 1-2 минуты

    7. Документация будет доступна по адресу: 

      https://<ваш-username>.github.io/<название-репозитория>/

    Например: https://vladimirsobol.github.io/labLexa/

    Шаг 3: Обновите URL в mkdocs.yml (опционально)

    После первого деплоя обновите mkdocs.yml:

    site_url: https://ваш-username.github.io/labLexa/
repo_url: https://github.com/ваш-username/labLexa
repo_name: labLexa

    Что происходит автоматически?

    • При каждом push в ветку main (если изменены файлы в docs/ или mkdocs.yml)
    • GitHub Actions автоматически:
    • Устанавливает Python и MkDocs
    • Собирает документацию (mkdocs build)
    • Деплоит на GitHub Pages

    Ручной запуск деплоя

    Если нужно запустить деплой вручную (без коммита):

    1. Перейдите в Actions → Deploy Documentation
    2. Нажмите "Run workflow"
    3. Выберите ветку main
    4. Нажмите "Run workflow"

    Для кого-то другого (кент)

    Если другой человек хочет задеплоить документацию:

    Вариант 1: Через ваш репозиторий (рекомендуется)

    1. Дайте ему права на репозиторий:
    2. Settings → Collaborators → Add people

    3. Дайте права Write или Admin

    4. Он должен: 

      git clone https://github.com/ваш-username/labLexa.git
cd labLexa
# Внести изменения в docs/
git add .
git commit -m "Update documentation"
git push origin main

    5. Деплой произойдёт автоматически после push

    Вариант 2: Форк репозитория

    1. Он делает Fork вашего репозитория
    2. Настраивает GitHub Pages в своём форке (Settings → Pages → GitHub Actions)
    3. Вносит изменения и пушит в свой форк
    4. Документация будет на его GitHub Pages

    Проверка деплоя

    После деплоя проверьте:

    1. Статус в Actions:
    2. Должна быть зелёная галочка ✅

    3. Если красный крестик ❌ - проверьте логи

    4. Доступность сайта:

    5. Откройте URL документации в браузере

    6. Должна открыться главная страница

    7. Если сайт не открывается:

    8. Подождите 1-2 минуты (GitHub Pages может обновляться с задержкой)
    9. Проверьте, что в Settings → Pages выбран "GitHub Actions"
    10. Проверьте логи в Actions на наличие ошибок

    Локальный просмотр (без деплоя)

    Если нужно просто посмотреть документацию локально:

    # Установите зависимости (если ещё не установлены)
pip install mkdocs mkdocs-material

# Запустите локальный сервер
mkdocs serve

# Откройте http://127.0.0.1:8000 в браузере

    Структура файлов для деплоя

    Убедитесь, что в репозитории есть:

    labLexa/
├── .github/
│   └── workflows/
│       └── docs.yml          # ← Workflow для деплоя
├── docs/                      # ← Файлы документации
│   ├── index.md
│   ├── backend/
│   └── ...
├── mkdocs.yml                 # ← Конфигурация MkDocs
└── README.md

    Troubleshooting

    Ошибка: "No workflow file found"

    • Убедитесь, что файл .github/workflows/docs.yml существует и закоммичен

    Ошибка: "Pages build failed"

    • Проверьте синтаксис mkdocs.yml
    • Проверьте, что все файлы в nav: существуют в docs/

    Документация не обновляется

    • Очистите кэш браузера (Ctrl+F5)
    • Проверьте, что изменения действительно запушены в main

    Нет прав на деплой

    • Владелец репозитория должен дать права Write или Admin
    • Или настроить GitHub Pages в Settings → Pages
