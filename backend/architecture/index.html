    Архитектура бекенда

    Общая структура

    Бекенд построен на Django REST Framework по архитектуре MVC (Model-View-Controller), где:

    • Models - модели данных (Django ORM)
    • Views - ViewSets для обработки HTTP запросов
    • Serializers - сериализация/десериализация данных
    • URLs - маршрутизация запросов

    Структура приложений

    config/

    Главный модуль Django проекта, содержит:

    • settings.py - конфигурация приложения, базы данных, REST Framework
    • urls.py - главный роутинг, подключение всех приложений
    • wsgi.py - WSGI конфигурация для деплоя

    rooms/

    Приложение для управления номерами гостиницы.

    Компоненты: - models.py - модель Room - views.py - RoomViewSet с дополнительными действиями - serializers.py - сериализаторы для Room - urls.py - маршруты для API номеров

    clients/

    Приложение для управления клиентами.

    Компоненты: - models.py - модель Client - views.py - ClientViewSet с поиском пересечений - serializers.py - сериализаторы для Client - urls.py - маршруты для API клиентов

    stays/

    Приложение для управления проживаниями (связь клиент-номер).

    Компоненты: - models.py - модель Stay с бизнес-логикой - views.py - StayViewSet с действием checkout - serializers.py - сериализаторы для Stay - urls.py - маршруты для API проживаний

    employees/

    Приложение для управления сотрудниками и расписанием уборки.

    Компоненты: - models.py - модели Employee и CleaningAssignment - views.py - EmployeeViewSet с управлением расписанием - serializers.py - сериализаторы для сотрудников - urls.py - маршруты для API сотрудников

    reports/

    Приложение для генерации отчётов.

    Компоненты: - views.py - QuarterlyReportView для квартальных отчётов - urls.py - маршруты для API отчётов

    common/

    Общие утилиты, используемые в разных приложениях.

    Компоненты: - utils.py - функции для работы с датами (parse_date_param, ensure_period)

    Паттерны проектирования

    ViewSet Pattern

    Все API endpoints используют ViewSets из DRF, что обеспечивает:

    • Стандартные CRUD операции из коробки
    • Кастомные действия через декоратор @action
    • Единообразную структуру кода

    Пример: 

    class RoomViewSet(viewsets.ModelViewSet):
    queryset = Room.objects.all()
    serializer_class = RoomSerializer

    @action(detail=True, methods=['get'])
    def clients(self, request, pk=None):
        # Кастомное действие
        pass

    Serializer Pattern

    Сериализаторы используются для:

    • Валидации входящих данных
    • Преобразования объектов в JSON и обратно
    • Контроля отображаемых полей

    QuerySet Optimization

    Использование select_related и prefetch_related для оптимизации запросов:

    queryset = Stay.objects.select_related('client', 'room')

    Бизнес-логика

    Валидация данных

    Валидация происходит на нескольких уровнях:

    1. Уровень модели - методы clean() в моделях
    2. Уровень сериализатора - валидация полей
    3. Уровень ViewSet - кастомная логика в perform_create()

    Расчёт стоимости проживания

    Логика расчёта находится в методе Stay.close():

    nights = (checkout_date - self.check_in).days
nights = max(nights, 1)  # минимум 1 ночь
self.total_cost = Decimal(nights) * self.room.daily_rate

    Проверка доступности номера

    При создании проживания проверяется переполнение номера через метод _count_overlapping_stays().

    API Документация

    Документация генерируется автоматически с помощью drf-spectacular:

    • OpenAPI 3.0 схема
    • Swagger UI интерфейс
    • ReDoc интерфейс

    Безопасность

    • CORS настроен через django-cors-headers
    • CSRF защита включена
    • Валидация всех входящих данных
    • Ограничения на уровне базы данных (unique constraints)

    База данных

    Поддерживаются две СУБД:

    • SQLite - для разработки (по умолчанию)
    • PostgreSQL - для продакшена

    Переключение через переменную окружения USE_SQLITE.

    Расширяемость

    Система легко расширяется:

    • Добавление новых моделей через создание приложения
    • Добавление кастомных действий через @action декоратор
    • Расширение сериализаторов для новых полей
    • Добавление новых фильтров через django-filter
